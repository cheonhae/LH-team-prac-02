## 질의 대비 (5분)

- 예상 질문 1: 기대값은 어떻게 계산했나요? → 답: 웹앱을 돌리기 전에 ④가 표본을 엑셀에서 열고 필터로 빈 값·같은 행을 찾아 셌습니다(합계는 7 − 4 = 3). 기대값과 근거는 `tests/acceptance.md` 2절에 있습니다.
- 예상 질문 2: 시작·근거 페이지는 CSV를 다시 계산하나요? → 답: 아니요. 집계 페이지가 저장한 `team1_app` 값만 읽습니다(`docs/design.md` 2절).
- 예상 질문 3: 어떻게 확인했나요? → 답: 배포 주소에서 `tests/acceptance.md` 3절 AC1~AC7을 하나씩 따라 했고 모두 통과했습니다(AC5는 `python tests/run_acceptance.py` 실패 0건). 판정은 사람이 화면에서 했고, '본 것'을 칸에 적었습니다.
- 예상 질문 4: 1인 조인데 리뷰는 어떻게 했나요? → 답: 팀 결정(`docs/team_decisions.md` 7단계)으로 자기 리뷰 후 병합을 했습니다. 병합 전 diff·`run_acceptance.py`·화면을 확인하고 PR 코멘트에 '자기 리뷰 — 확인한 것'을 남겼습니다. AI는 승인·병합하지 않았습니다.
- 예상 질문 5: 교차 검증 결과는? → 답: 받은 이슈는 #15 한 건이고, 신고한 조가 판정 '통과'로 직접 닫아 수정·보류가 없습니다. 기준표 교차 검증 칸은 채우지 못해 미검증으로 둡니다.
- 예상 질문 6: 문제가 생기면? → 답: 해당 PR 화면에서 Revert로 되돌리는 PR을 만들어 병합하고, 배포 주소에서 AC1~AC7을 다시 봅니다(`README.md` 0절).
- 영상에 덜 나온 칸이 있으면: 이슈·PR 이력은 `README.md` 0절 PR 목록과 5절, 검증 결과는 `tests/acceptance.md` 3절로 보충합니다.
