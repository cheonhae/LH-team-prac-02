## 1. 요구사항과 완료 기준

PRD 3.2의 핵심 기능 세 가지를 R1~R3으로 두고, PRD 5.2의 S1~S4와 이었습니다. S4(시작 페이지 요약·백업·비우기)는 R2의 판정을 시작 페이지에서 다시 보는 것이라 R2에 붙였습니다 [가정].

| ID | 요구사항 (PRD 3절) | 성공 시나리오 (PRD 5절 S 번호) | 실패할 때 동작 | 경계 조건 |
|---|---|---|---|---|
| R1 | CSV 붙여 넣기와 제외 — 집계 페이지에서 민원대장 CSV를 붙여 넣으면 중복·빈칸 행을 사유와 함께 제외한다 | **S1** — 집계 페이지에서 표본 CSV를 붙여 넣고 [집계]를 누르면 → 같은 페이지에 전체 행·제외 행 수가 보이고, 값이 ④의 기대값과 같다 | 텍스트 칸이 비었거나 머리글에 접수번호·접수일·유형·처리상태 열이 없으면 이유를 화면에 알리고 저장하지 않는다(기존 저장값 유지) | 빈칸이면서 중복인 행 → 사유 '빈칸' 하나. 처음 나온 행은 남기고 뒤의 같은 행만 중복. 완전히 빈 줄은 세지 않음. 칸 수가 모자란 행은 빈칸으로 봄. 데이터 행이 0개여도 오류 없이 전체 0·제외 0으로 처리 |
| R2 | 건수표와 합계 판정 — 남은 행의 유형별·처리상태별 건수를 세고 `전체 − 제외 = 유형별 합계 = 처리상태별 합계`이면 "일치", 아니면 "불일치". 시작 페이지는 전체·제외·합계·판정을 요약으로 보여 준다 | **S1**(같은 페이지에 건수표와 "일치" 판정) + **S4** — 시작 페이지로 돌아오면 요약(전체·제외·합계·판정)이 보이고, [백업 내보내기]로 JSON을 받고, [비우기]를 누르면 요약이 비워진다 | 하나라도 다르면 "불일치"를 숨기지 않고 세 값을 나란히 보여 준다. 집계 전에 시작 페이지를 열면 "저장된 데이터가 없습니다. 집계 페이지에서 먼저 붙여 넣으세요" 안내. 가져오기 파일의 모양이 틀리면 오류를 알리고 저장하지 않는다 | 남은 행이 0개(전부 제외)면 건수표는 비고 합계 0 = 0 = 0으로 "일치". 유형·처리상태 값이 한 종류뿐이어도 표가 나온다. 집계를 다시 하면 이전 결과를 덮어쓴다. 판정·사유 옆에는 항상 "담당 검토 후 확정" 표시 |
| R3 | 제외 행 근거 — 근거 페이지가 제외 행의 원본 행 번호·사유·원본 값을 표로 보여 주고 `excluded_rows.csv`로 내려받게 한다 | **S2** — 근거 페이지로 이동하면 → 제외 행 표가 보이고 행 수가 집계 페이지의 제외 행 수와 같다. **S3** — [excluded_rows.csv 내려받기]를 누르면 → 화면 표와 같은 행의 CSV가 받아진다 | 집계 전이면 "집계 페이지에서 먼저 붙여 넣으세요" 안내하고 내려받기 버튼을 누를 수 없게 한다(또는 눌러도 파일을 만들지 않는다) | 제외 행이 0개면 "제외된 행이 없습니다"를 보여 주고 머리글만 있는 CSV(또는 내려받기 없음)로 처리 — [가정] 머리글만 있는 CSV. 값에 쉼표가 있어도 CSV 칸이 깨지지 않게 큰따옴표로 감싼다 |

- 모든 시나리오에서 판정·사유 옆에 "담당 검토 후 확정"이 보인다(AC6).
- 데이터를 밖으로 보내지 않는다(AC5, `python tests/run_acceptance.py`).
