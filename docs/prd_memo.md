# PRD 메모 — 팀원 A (1조)

> 팀 PRD 인터뷰 전에 쓰는 거친 메모입니다. 확정된 내용이 아니며, 인터뷰 뒤 `prd/team_prd.md`로 옮겨 다듬습니다.

## 1. 무엇이 불편한가

- 매주 받는 민원대장 CSV에는 같은 민원이 두 번 들어간 행과 필수 칸이 빈 행이 섞여 있다.
- 지금은 이런 행을 눈으로 찾아 지운 뒤 유형별·처리상태별 건수를 센다. 그래서 합계가 전체 행 수와 왜 다른지 설명하기 어렵다.
- 무엇을 왜 뺐는지 기록이 남지 않아 다음 사람이 같은 숫자를 다시 만들 수 없다.

## 2. 누가 쓰나

- 주간 민원 건수를 집계해 보고하는 민원 담당자(가상)
- 그 집계를 받아 확인하는 검토자(가상)

## 3. 무엇으로 줄이나 (오늘 만들 것)

여러 페이지 HTML 웹앱입니다. 서버 없이 파일을 더블클릭하거나 Pages 주소로 엽니다.

1. **집계 페이지**
   - CSV를 불러와 중복 행과 빈칸 행을 제외한다.
   - 남은 행으로 유형별·처리상태별 건수표를 만든다.
   - "합계 = 전체 행 − 제외 행"이 맞는지 판정해 일치·불일치로 보여 준다.
2. **제외 행·근거 페이지**
   - 제외한 행마다 원본 행 번호, 제외 사유(중복/빈칸), 원본 값을 표로 보여 준다.
   - 이 표를 `excluded_rows.csv`로 내려받는다.

## 4. 검증 절차

- 계산 검산: 유형별 합계, 처리상태별 합계, 전체 행 − 제외 행이 모두 같은 숫자인지 확인한다.
- 제외 판단은 도구가 사유를 붙여 보여 주기만 한다. 최종 처리는 "담당 검토 후 확정"으로 둔다.

## 5. 만들지 않을 것

- 서버·로그인·DB
- 실제 민원 자료(가상 표본만 사용)
- 차트
- 보고서 문장 자동 작성
- 대장 수정·정합 기능
- 외부 라이브러리

## 6. 아직 정할 것 (인터뷰 때 묻기)

- 중복의 기준: 모든 칸이 같아야 중복인가, 접수번호만 같아도 중복인가?
- 빈칸의 기준: 어느 열이 비면 제외하는가(예: 유형, 처리상태)?
- 표본 CSV의 열 이름과 행 수(④ 팀원 B와 맞추기)
