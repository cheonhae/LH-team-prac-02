# 팀 PRD — 1조 주간 민원대장 집계 검증 웹앱

> 팀 PRD 인터뷰(코어 페이스) 결과 · 출발점: 팀원 A의 `docs/prd_memo.md` · 프로젝트 카드: `docs/project_card.md`
> 인터뷰에서 정하지 않은 것은 **[가정]**으로 적고 `docs/team_decisions.md`에도 남겼습니다.

## 1. 프로젝트 개요

- **해결하려는 문제:** 주간 민원대장 CSV에서 중복·빈칸 행을 눈으로 찾아 지우는 수작업에 매주 시간이 많이 든다.
- **배경:** [가정] 주간 민원 건수를 매주 보고해야 해서 같은 수작업이 매주 반복된다.
- **기대 변화:** 수작업으로 걸러 낸 뒤 계산기로 합계를 맞춰 보던 것 → 합계 일치 판정("합계 = 전체 행 − 제외 행")이 자동으로 바로 나온다.

## 2. 사용자 분석

- **주 사용자:** 매주 민원대장을 받아 건수를 집계해 보고하는 민원 담당 실무자(가상).
- **사용 맥락:** 매주 정해진 요일(예: 월요일 오전), 지난주 대장 CSV를 받은 직후, 보고서를 쓰기 전에 연다.
- **현재 해결 방식과 한계:** 엑셀에서 정렬·필터로 중복·빈칸을 눈으로 찾아 지우고 피벗이나 COUNTIF로 센다. 한계는 두 가지다. 매주 같은 조작을 반복하고, 무엇을 왜 뺐는지 기록이 남지 않는다.

## 3. 기능 요구사항

### 3.1 페이지와 하는 일

| 페이지 | 파일 | 하는 일 | 담당 |
|---|---|---|---|
| 시작 페이지 | `tools/index.html` | 메뉴, 저장된 데이터 요약(전체·제외·합계·판정), JSON 백업 내보내기·가져오기, 비우기 | ① 팀원 A |
| 기능 A: 집계 페이지 | `tools/pages/tally.html` [가정: 파일 이름] | 민원대장 CSV를 붙여 넣으면 중복·빈칸 행을 사유와 함께 제외하고, 유형별·처리상태별 건수표와 합계 일치 판정을 보여 준다. | ② 팀원 A (팀원 B에서 넘겨받음) |
| 기능 B: 근거 페이지 | `tools/pages/evidence.html` [가정: 파일 이름] | 집계 페이지가 제외한 행의 원본 행 번호·사유·원본 값을 표로 보여 주고 `excluded_rows.csv`로 내려받게 한다. | ③ 팀원 A |

### 3.2 핵심 기능 (우선순위 순)

1. **CSV 붙여 넣기와 제외** (집계 페이지): 표본 CSV 내용을 텍스트 칸에 붙여 넣으면 중복 행과 빈칸 행을 사유와 함께 제외한다.
   - [가정] 빈칸 기준: 접수번호·유형·처리상태 중 하나라도 비어 있으면 '빈칸'으로 제외한다.
   - [가정] 중복 기준: 모든 열 값이 앞에 나온 행과 같으면 '중복'으로 제외하고, 처음 나온 행은 남긴다.
   - [가정] 한 행이 빈칸이면서 중복이면 사유는 '빈칸' 하나로 적는다.
2. **건수표와 합계 판정** (집계 페이지): 남은 행으로 유형별·처리상태별 건수를 세고, 다음 세 값이 모두 같으면 "일치", 아니면 "불일치"로 보여 준다.
   - 전체 행 − 제외 행
   - 유형별 합계
   - 처리상태별 합계
   - 전체 행은 머리글 줄을 뺀 데이터 행 수다. [가정]
3. **제외 행 근거** (근거 페이지): 원본 행 번호·사유(중복/빈칸)·원본 값을 표로 보여 주고 `excluded_rows.csv`로 내려받는다.

- 판정·사유 옆에는 "담당 검토 후 확정"을 함께 표시한다. 도구는 판단을 확정하지 않는다.

### 3.3 차별점

엑셀처럼 지우고 끝나지 않는다. 뺀 행마다 사유와 원본 값이 남고, 그 근거를 `excluded_rows.csv`로 내려받을 수 있다.

### 3.4 '다음'으로 미룰 것

- 중복·빈칸 기준을 화면에서 바꾸기
- 여러 주 대장을 비교하기
- 검토자 확인 표시
- CSV 파일 선택으로 불러오기(이번에는 붙여 넣기만)

### 3.5 만들지 않을 것

서버·로그인·DB, 실제 민원 자료, 차트, 보고서 문장 자동 작성, 대장 수정·정합 기능, 외부 라이브러리.

## 4. 비기능 요구사항

### 4.1 형태와 사용 환경

- `tools/` 아래 여러 페이지 HTML 웹앱이다.
  - `index.html`: 시작·메뉴·요약·백업
  - 기능 페이지 2개: `pages/`
  - 공통 파일: `assets/common.js`, `assets/style.css`
- 사무실 PC 브라우저에서 연다. 서버 없이 파일을 더블클릭해 열어도, GitHub Pages 주소로 열어도 동작한다.
- 완성하면 병합된 main을 GitHub Pages로 배포한다.
- 서버·로그인·설치·외부 라이브러리·외부 주소·외부 전송은 없다.

### 4.2 페이지 사이 흐름

- 집계 페이지가 붙여 넣은 CSV로 만든 결과를 저장한다. 결과는 전체 행 수, 제외 행 목록(원본 행 번호·사유·원본 값), 건수표, 판정이다.
- 근거 페이지는 그중 제외 행 목록을 읽어 표와 `excluded_rows.csv`를 만든다.
- 시작 페이지는 전체·제외·합계·판정을 읽어 요약으로 보여 준다.
- [가정] 근거 페이지와 시작 페이지는 읽기만 하고 CSV를 다시 계산하지 않는다. 집계 전에 열면 "집계 페이지에서 먼저 붙여 넣으세요"라고 안내한다.

### 4.3 저장

- 브라우저 안 localStorage 키 하나에 JSON으로 저장한다. [가정: 키 이름 `team1_app`, JSON 모양은 `docs/design.md` 2절에서 확정]
- 저장소는 공통 함수(`assets/common.js`)로만 쓴다.
- 시작 페이지에서 JSON 백업 파일로 내보내고 가져온다. '비우기'로 저장된 데이터를 지운다.

### 4.4 데이터

- 실제 자료는 넣지 않는다. 가상 표본(`data/team_sample.csv`, UTF-8)으로만 시험한다.
- [가정] 표본 열: 접수번호, 접수일, 유형, 처리상태, 내용요약. 행 수와 일부러 넣은 중복·빈칸 행은 ④ 담당(팀원 A)이 정한다.
- 입력 방법은 붙여 넣기만 쓴다. 표본 CSV 내용을 복사해 집계 페이지의 텍스트 칸에 붙여 넣는다. 파일 선택은 쓰지 않는다.

## 5. 성공 지표

### 5.1 성공 모습

표본 CSV를 붙여 넣으면 건수표의 합계 일치 판정과 제외 행 근거를 확인하고 `excluded_rows.csv`를 내려받을 수 있다.

### 5.2 성공 시나리오 (페이지를 오가며 화면에서 판정)

| ID | 어느 페이지에서 무엇을 하면 | 어디에 무엇이 보인다 |
|---|---|---|
| S1 | 집계 페이지에서 표본 CSV를 텍스트 칸에 붙여 넣고 [집계]를 누르면 | 같은 페이지에 유형별·처리상태별 건수표와 전체 행·제외 행·합계, "일치" 판정이 보인다. 값은 ④가 미리 계산한 기대값과 같다. |
| S2 | 근거 페이지로 이동하면 | 제외 행 표(원본 행 번호·사유·원본 값)가 보이고, 표의 행 수가 집계 페이지의 제외 행 수와 같다. |
| S3 | 근거 페이지에서 [excluded_rows.csv 내려받기]를 누르면 | 화면 표와 같은 행이 담긴 `excluded_rows.csv`가 받아진다. |
| S4 | 시작 페이지로 돌아오면 | 저장된 데이터 요약(전체·제외·합계·판정)이 보인다. [백업 내보내기]로 JSON 파일을 받고, [비우기]를 누르면 요약이 비워진다. |

- 모든 시나리오에서 판정·사유 옆에 "담당 검토 후 확정"이 보인다.
